# 赐福地图原型接入工单

日期：2026-10-13｜依据：用户确认的新设计方向与复用优先计划。

## 1. 选型依据与本轮目标

统筹已读取部门下载的精确候选元数据和 API 取证，确定先验证以下最小组合：

- Waystones `21.1.46`，NeoForge 1.21.1，节点与传送能力来源。
- Balm `21.0.66`，满足 Waystones 声明的 `[21.0.39,)`。
- JourneyMap `1.21.1-6.0.9`，已内嵌 JourneyMap API `2.0.0-1.21.1` 和 common-networking `1.0.21-1.21.1`；试装核对嵌套 JAR 真的加载，不额外重复塞入另一版本。
- 当前 NeoForge `21.1.219` / Java 21 保持。候选元数据允许该版本，不等于实机兼容已通过。

JMI `1.9.1` 本轮不设为必装：取证表明它的 Waystones marker popup 回调直接返回，点击行为创建/切换 waypoint，没有实现本项目所需旅行请求。Waystones 本身已有 JourneyMap 集成与节点列表/更新/删除同步。先使用本体与公开地图 API；确有独立收益时才补 JMI。

这一步复用节点数据库、发现/命名/撤销和传送能力，在 EldenCombat 中只补赐福语义与地图入口。第一阶段允许以原版 Waystones 方块验证协议，必须注明它是占位原型；随后接简单原版风格赐福视觉与交互，不能将“能传送的普通传送石”作为最终赐福交付。

## 2. 当前已有接口证据

证据目录：`docs/research-evidence/reuse-audit-20261013/`。

- `waystones-public-api.txt`：`getWaystone(server, UUID)`、`isWaystoneActivated(player, node)`、`getActivatedWaystones`、`activateWaystone`、`placeWaystone`、默认 destination 与 teleport context 的公开入口。
- `waystones-teleport-api.txt`：节点 UID、维度、位置、owner、visibility、isValid；传送 context 和 `WaystoneTeleportEvent.Pre`。
- `balm-events-api.txt`：BalmEvent 在目标版本实现 NeoForge ICancellableEvent，可用于统一阻断不合法旅行；实际事件路径还需复验。
- `waystones-native-map-bytecode.txt`：Waystones 本身监听 list/update/remove 与 JourneyMap mapping 事件，同步自身 waypoint。
- `jmi-waystones-bytecode.txt`：JMI marker 的菜单回调为空；这不是普通玩家安全旅行完成证据。
- `*-jar-metadata.txt` 与候选 JAR：绑定精确来源/版本/哈希，禁止改用未记录文件。

许可按完整官方依赖处理；不把 Waystones/JourneyMap/Balm 的代码或资源复制到自研 JAR。具体分发方式在候选入包前核对。API 的读取和薄适配不能演变为重打包第三方本体。

## 3. 战斗部门执行顺序

### G-C1 最小组合启动

完成 R-C0 报告的核心回执后直接执行本工单，不必等其他低优先候选全部研究完。

1. 保存当前修改前文件；以已归档的0.2.0测试候选为基线，在工作区独立运行目录/新测试存档安装以上最小组合。现有玩家实例、存档、正式dist和基础七模组锁先不覆盖。
2. 候选来源/文件大小/哈希对齐官方版本记录；检查外部和嵌套依赖、NeoForge加载、客户端地图打开和专用服务端启动。
3. 出现不兼容时先记录真实加载错误并判断具体版本/API原因；不能因一次失败直接重新实现地图或迁移MC版本。

### G-C2 实际节点与赐福语义

沿用 Waystones 的真实节点 UID、位置、维度、名字、发现状态与有效性。若需自己的赐福标记/奖励元数据，只保存必要附加字段并引用真实 UID，不重复维护另一套节点位置或发现数据库。

先放置两真实节点、激活、命名、保存重进；普通玩家与不同玩家的发现数据分开。明确哪些节点具有赐福语义：测试阶段的占位节点与最终古老/自建赐福要可区分。公开节点的可访问规则按真实服务端状态判断，客户端不得自选public或owner。

赐福休息恢复现有 FP；沿用现有 FP 数据/保存逻辑。休息需实际合法交互，不通过打开地图、查看任意 waypoint 或重复非法请求补满。床与原版重生机制保留。技能管理先列明接口，首个战灰绑定进入下一遗迹工单；不塞入一套新的成长框架。

### G-C3 地图入口与统一服务端规则

使用目标 JourneyMap API v2 的公开插件/事件/marker/context-menu 能力增加赐福入口；优先复用可明确关联真实节点 UID 的显示数据。若需要自有 marker，放在自有 namespace；通过正式配置或自身数据避免重复图标，不能修改 JourneyMap 本体或依赖私有反射。

地图动作仅发节点 UID 与必要请求标识，不发可信任的任意坐标。服务端重新取得真实 Waystones 节点并检查：

用户已明确确认出发规则：非战斗时可从野外地图前往已发现赐福。这是正式玩法要求；可额外保留服务器限制配置，但默认和验收不得缩成仅节点旁。近节点测试只是早期协议夹具；必须补非OP玩家野外实际地图发起成功，以及野外战斗/未发现/失效节点拒绝。实现不得依靠unchecked/force调用获得野外出发能力，应核对合法context/配置/requirements扩展。

- 请求玩家连接/生命/施放和战斗状态；不把“未施放技能”简单当成“不在战斗”。战斗状态要覆盖受击和造成伤害后的有效时间。
- 节点存在、有效、属于登记的赐福范围；该玩家已发现或满足公共访问规则。未知、删除、伪造 UID、普通自建 waypoint 均不能授权。
- 所有权、公共/私人配置、合法目标维度、边界、区块加载与安全落点；不长驻加载所有节点区块。
- 成本/冷却与并发请求去重；避免重复扣费、重复旅行和失败时误扣。数值是可配置草案，不能写成用户确认的最终平衡。

调用正常校验的 Waystones context/tryTeleport 路径；不得用 force/unchecked 路径或OP命令绕过规则。核实其异步完成结果回到正确服务端执行上下文、失败可反馈、脱线/节点撤销不留下瞬态。

原生 Waystones 菜单、道具等可达到同一赐福的入口也需统一规则，可用目标版本 Pre 事件或已核实 requirement 扩展。不能让自有地图入口拒绝战斗旅行，另一个原生菜单却能直接跳过。如果现成接口无法支持，提交具体缺口再做最小补丁，不放松验收。

### G-C4 验证与交接

优先跑与此次接入相关的验证，保留真实失败及修复原因。已有八技全量通过记录不必无变更重复；新增模块不得使基础启动/FP保存/战技输入回归。

| 场景 | 必须看到的证据 |
| --- | --- |
| 两节点 | 放置、激活、命名、地图关联真实UID；普通非OP玩家离开节点到野外后通过实际地图操作旅行 |
| 保存 | 真实退出/重启后节点、名字、发现/权限与旅行可用；沿用现有FP存储 |
| 未发现/未知 | 正常玩家请求未授权UID、普通路径点或伪造坐标失败，无位移/错误扣费 |
| 删除/撤权 | 节点删除或权限变化后旧客户端图标不能继续授权；同步失效显示 |
| 战斗 | 造成伤害和受击后拒绝；允许条件恢复后成功；原生菜单/道具入口同样遵守 |
| 落点/维度 | 无安全落点、无效维度等拒绝；有效跨维度/按需区块旅行成功，无长期全节点强加载 |
| 多人 | 两真实玩家发现/私人数据不串；公共规则、owner拆除权限按服务器配置生效 |
| FP与输入 | 合法赐福休息恢复FP；非法/远程查看不恢复；既有战技按键不冲突 |
| 依赖与两端 | 客户端、专用服务端精确组合启动；地图客户端类不泄漏进服务端入口；可选依赖缺失时行为明确 |

区分实际鼠标菜单操作、引擎测试/harness触发、纯单测。测试直接调用处理器不能冒充地图点击已完成；普通玩家测试不能使用OP传送权限。

报告写入 `docs/GRACE-PROTOTYPE-REPORT-20261013.md`，保存依赖/配置/JAR与资源哈希、日志、截图、测试玩家权限、失败/跳过项。首轮占位协议、最终赐福显示与整合包发布分别记录状态。

## 4. 美术部门执行顺序

### G-A1 最小赐福视觉与接口

R-A0 核对现成资源后直接接本任务，与战斗的协议验证并行；不启动剩余3D武器批次。

- 先清点可复用的本地图标与官方依赖资源，缺口才制作原创16×16/必要32×32像素资源。
- 交付地图赐福图标（已发现、自建/古老、公共/私人、失效的可读区分），以及简单原版风格的休息/旅行/战灰入口资源。优先颜色加小符号，不堆砌复杂UI。
- 小型赐福方块/贴片方案与 Waystones 的实体/节点交互边界先向战斗提交，确认API可实现后再制作；不可为了外观另建节点网络。
- 构图以MC原版像素、有限色阶和灰色界面为准。图标与空间光效分开：地图不画电影海报式大特效，空间赐福可以使用简单金色像素贴片/粒子。
- 提供清楚的文件/ID、透明背景、像素尺寸、帧顺序/周期、锚点、状态语义、可编辑源与许可/哈希。禁止从ARR资产抽取重打包；只作官方依赖使用与原创补充。

设计交接写入 `docs/GRACE-PIXEL-ART-HANDOFF-20261013.md`。预览不能替代实机地图缩放、界面可读性和实际方块交互验收。

已交资源映射采用美术 `art/grace-pixel/assets.json` 的实际路径：`textures/map/grace_<ancient|player>_<state>.png`、`textures/ui/grace_<rest|travel|ashes>.png`、`textures/fx/grace_<flame|ground>.png`。战斗报告中gui/grace路径是早期建议，不再另制一套。Waystones服务端origin中的generated明确映射ancient，player映射player；visibility/valid/discovered到最终状态由服务端语义明确转换。资源ID不是节点UID，不向客户端赋予权限；未发现默认隐藏，invalid可短暂提示后删除。四帧flame按16×16帧采样，禁止把16×64图直接当方形贴片。

### G-A2 普通装备缺口收束

Spartan 为优先试装候选；Simply Swords 保留备选。法杖、圣印记和盾牌先查同版本现成内容，不能因第一套不覆盖就全部自行重画。交一张逐类别“已覆盖/可适配/未覆盖”清单，后续只给确切缺口安排像素资源。

已交的覆盖表是源提交的资源basename，下一步从精确发布JAR核对注册ID、贴图实际像素尺寸/色板/柄部透明区域与模板引用；读取或隔离预览不等于把素材复制进正式资源。至少先看匕首、大型剑、矛、长弓代表PNG，避免仅凭generated/handheld的JSON声明判断质感。现成图标覆盖不了的类别仍如实记缺口。

外部武器试装前由战斗核对namespace边界：WeaponStacks.definition、Weapons.profileOf、WeaponAttributes等当前入口只读item path，有同名外部物品误套自有参数风险。修为本模组明确匹配/完整ResourceLocation映射，并保留合法标签回退。用一个同path不同namespace的反例与自有成长保存验证；随后只试装一把已确认的Spartan武器，不重复制所有Item或叠加两套基础属性。

## 5. 排程

战斗负责唯一构建、运行资源同步、启动、候选安装与服务端/网络；美术只修改自己的原创资源和交接文件。双方使用各自报告路径，不覆盖共享源。根统筹不另开实现线。

当前在途研究先收束核心证据；G-C1/G-A1可以开始。G-C4完成后进入一个自然生成遗迹→关键奖励→普通武器战灰绑定/施放的工单；整合包最终完成范围不因两节点原型通过而缩小。
