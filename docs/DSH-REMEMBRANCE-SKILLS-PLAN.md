# 给 dsh：八件追忆武器专属战技实施计划

日期：2026-10-11。工作区：`D:/codexout/mcmod`。

## 任务与分工

用户已将专属战技代码交给 dsh。目标是基于现有 Epic Fight 接入做固定专属战技，不重写一套玩家战斗引擎。

- dsh：技能注册、玩家动作、服务端判伤与位移、FP、同步、特效、测试和构建。
- Codex：游戏版武器的连续曲面、贴图降噪、连接处和美术验收。平滑改版尚未交付，当前资源仍是上一版。
- 不做处决，不新增普通跳跃攻击；指定战技可以跃起。保留玩家皮肤，Boss 暂停。
- 本轮先做八个固定追忆战技，不扩展到 33 类型武器、战灰替换界面、法术系统或整个整合包重构。
- 不覆盖其他 agent 未提交的改动。开工先读当前文件和工作区差异，不依据本计划盲目替换现有实现。

## 代码结构与施放契约

沿用仓库包名和注册习惯，以下类名是建议，不是要求另建重复系统：

| 建议模块 | 职责 |
| --- | --- |
| `compat/skills/RemembranceSkills` | 接入现有 SKILLS 注册，绑定八个固定技能 |
| `compat/skills/*Skill` | 各战技的 EF 请求入口、阶段行为和合法追击 |
| `compat/animations/RemembranceAnimations` | 独立玩家动画注册、Phase、collider 与事件时点 |
| `server/skills/SkillCastState` | 每玩家施放实例、阶段、开始 tick、追击时窗、去重与清理 |
| `server/skills/PlayerFpState` | 全局 FP、冷却与权威快照；不放入共享 Skill 单例 |
| `entity/skill/*` | 黄金波、火焰波等确需独立寿命的服务端命中体 |
| `network/*`、`client/*` | 必要状态同步与表现，不能接受客户端上报伤害或目标列表 |

先检查现有状态是否已由另一 agent 添加；可复用时不重复实现。

1. 从 EF `WEAPON_INNATE` 技能输入发起。使用当前版本支持的注册和 moveset API；本地旧 `WeaponCapability.Builder.innateSkill` 已标为弃用，不把它当优先的新接口。
2. 一个服务端入口验证实际武器、战斗模式、存活、施放状态、FP、冷却和移动许可。客户端预测只做表现；拒绝请求不扣费、不生成命中体。
3. 服务端分配施放 ID。同一阶段提交只能扣费、启动一次；追击验证所属施放、顺序和服务端时窗。请求身份不能由客户端随意更换以绕过限制。
4. 建议状态流：`IDLE -> WINDUP -> ACTIVE -> FOLLOWUP_WINDOW/RECOVERY -> IDLE`；终止走统一 `cancel/finish` 清理。每阶段最大时长有上界。
5. 使用独立 FP attachment，不借用各 SkillContainer 的 WEAPON_CHARGE 伪装共享 FP。首次进入原型默认满 FP；换武器/换技能/换维度不补满，重生原型默认补满并明确记录。退出保存，重新登录不得刷恢复；死亡、克隆和同步行为必须测试。
6. FP 消耗一旦确认默认不退；多段技能仅对确认启动的段扣费。共用校验与扣费事务，禁用 EF 自带重复扣费，但保留其输入、动画与施放生命周期。
7. 近战采用 EF AttackAnimation.Phase/collider；波、冲击和延迟血焰走单一服务端效果链。若同段同时有近战与冲击，明确哪些可叠加，不能由两套引擎意外叠加。
8. 每段以目标实体和命中通道去重，多段技能允许下一段重新命中。确认扣血成功再触发吸血、状态和后续收益；无敌、友军拒绝、未造成伤害不产生吸血。
9. 多段伤害明确 Minecraft 受击冷却的处理方式并实测；不能只播放三段特效而实际上只扣一次血，也不能全局清零所有实体无敌时间。
10. 跃起由服务端控制位移与时长，优先 EF 动画移动能力，不另开每 tick 无约束传送。限制水平距离、转向和高度，处理低天花板、悬崖、台阶、水、碰撞及超时未落地。
11. 切武器、死亡、离线、维度切换、受击中断、动画终止和超时均清理临时移动/重力修改；只撤销本技能施加的修改，不覆盖其他系统原有状态。已生成效果的继续或消失策略逐项定义，不能变成永续伤害。
12. `Skill` 和动画注册对象可能共享；施放状态放玩家/容器，不修改共享 EF 动画 Phase 来临时加伤。专属动画两端注册一致；缺失资源单独诊断。

当前 `ordinary_air_combo` 与 `CAST_SKILL` 钩子属于基础攻击策略；专项测试它们不拦截、不替换专属技能。保留 `no_execution_damage` 与禁用 THE_GUILLOTINE 的政策，不为命定之死开放处决标签。

以下全部是可调整的同人原型值，不宣称原作数值。按 20 TPS 计算，服务端用整数 tick。独立配置管理，不硬写散落常量。

| 战技 | FP 初值 | 建议动作时长 | 初版限制 |
| --- | --- | --- | --- |
| 黄金波动 | 20 | 蓄势 10 + 释放 4 + 收招 10 tick | 波最长传播 16 格，寿命上限 30 tick；每目标一次 |
| 黄金碎击 | 22 | 蓄势 8 + 跃起/落槌约 16 + 收招 10 tick | 水平位移最多 4 格，高度最多 2 格；冲击半径 3 格 |
| 命定之死 | 25 | 蓄势 8 + 三个伤害阶段共约 24 + 收招 10 tick | 残留最多 60 tick；重复施放刷新而不无限叠层 |
| 掠夺火焰 | 20 | 蓄势 9 + 释放 4 + 收招 10 tick | 波最长 12 格；单次施放总治疗上限 4 生命值 |
| 水鸟乱舞 | 28 | 蓄势 10 + 三组斩击共约 36 + 收招 10 tick | 水平总位移最多 6 格，每组最多 2 格；逐组去重 |
| 唤星 | 15 + 15 | 呼喊 8 + 牵引 6；追击动作约 24 tick | 呼喊后追击窗 12 tick；牵引范围 5 格，不能隔墙牵引 |
| 授血仪式 | 每段 15 | 每段蓄势 6 + 生效 4；段间输入窗 10 tick | 最多 3 段，半径 4 格；FP 不够就拒绝下一段 |
| 咒血斩击 | 12 + 8 | 首段 8 + 6；追击动作约 18 tick | 追击窗 10 tick；血焰延迟 4 tick、每段每目标一次 |

原型 FP 上限建议 100，不改现有治疗瓶为回蓝瓶；回蓝物品另列后续任务。测试可提供仅限权限玩家的设置 FP 命令。

时长不机械乘现有 1.15 攻速钩子：明确专属技能是否受攻速影响，动画、命中事件、追击窗与特效采用一致时钟。保持短蓄势、明确命中和可辨收招；不得通过客户端单独加速造成动作先到、服务端伤害后到。

命定之死初版使用短时、可清理且有总量上限的效果；不要永久削减最大生命属性。出血和韧性不是本轮新建系统，已有可靠接口才接；没有则明确标记未实现，不能用视觉冒充。

## 特效与美术接口

- 粒子、斩痕和波形跟随实际服务端施放与命中时点；伤害框不由粒子数量决定。
- 斩痕短寿命并设置活动数量上限。不得每 tick 广播整张目标清单、生成无限持久实体或按每个模型方块发粒子。
- 武器渲染不因战技重建网格。图集、模型 ID、握持原点保持兼容；不要修改 `art/remembrance-game/`、`art/remembrance/`、`art/tooling/` 或覆写美术验收文件。
- 玩家动作需要的自制动画由 dsh 放在模组动画资源路径，不要把它误写成武器 root 的局部动画。
- 碎星单物品的副手剑为动作限定的视觉实例，不赠送可丢弃第二件物品，不复制库存。左右剑 collider 各自明确且共享该段去重策略；结束、换手和切物品恢复原副手显示。
- 若需修改 `WeaponItemRenderer`、item_skins 或握持轴，先记录具体物品、局部矩阵与理由，并单独提交，避免与 Codex 的平滑模型交付冲突。
- 保持 mesh 已是 blocks、下原点 V、游戏加载只翻 V 一次的契约；不能为了战技把模型再除以 16。

## 实施顺序

1. **基础设施**：确认注册、原子扣费、施放状态、清理与测试。先用一个技能打通完整请求，不先铺八套重复代码。
2. **黄金波动**：验证地面传播、墙体、坡面、去重、FP 和其他玩家可见。作为远程地面效果模板。
3. **黄金碎击**：验证技能跃起、碰撞、落地一次结算和中断恢复。作为位移/冲击模板。
4. **掠夺火焰、咒血斩击**：复用效果生命周期，分别补吸血、延迟命中和追击。
5. **授血仪式、命定之死**：补多阶段扣费、伤害间隔、状态刷新与清理。
6. **水鸟乱舞、唤星**：最后处理高风险多段空中动作与虚拟双剑；不能只给这两把换个基础攻击动画就验收。
7. **发布验收**：构建、专服、双人联机、锁定整合包兼容；先报告结果，别直接覆盖用户现用整合包或存档。

每批交付一个可验证版本，失败先修再扩展。参数和独立特效可以复用，禁止为了“统一”改掉八把武器的动作身份。

## 验收门槛

| 测试 | 必须证明 |
| --- | --- |
| 注册与物品绑定 | 八个 ID 两端一致，持对应武器显示并施放正确技能，普通攻击不退化 |
| 消耗与追击 | FP 不足、非法武器、过期追击、重复请求不扣费；合法每段只扣一次 |
| 真实命中 | 正前方/侧边/范围边缘/贴身分别测试，命中时点与动作一致；多段真实扣血并有上限 |
| 遮挡与地形 | 实墙不穿透；台阶、坡面、低顶、悬崖不卡死、不异常飞行、不反复落地判伤 |
| 生命周期 | 施放中切武器、死亡、离线、换维度、受击、超时均无残留重力/锁动作/无限效果 |
| 特殊收益 | 吸血只来自有效伤害且总量受限；命定之死不会永久改最大血量；牵引不隔墙 |
| 多人 | 两名玩家同时施放不串状态；远端动作和特效可见；延迟与重复请求不双倍伤害 |
| 策略边界 | 无处决伤害；仅许可战技能技能跃起；Boss 代码和普通空中攻击策略未被扩展 |
| 资源与兼容 | F3+T 后仍可施放、附魔与双持不坏；专服无客户端类加载；实际装包组合单独验证 |

必须同时有纯逻辑测试和游戏内结果。基础 smoke 目前不是专属技能断言，需新增权限隔离的技能测试场景，不以 Gradle 成功替代真实命中验收。
