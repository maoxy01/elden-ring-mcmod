# 所有物品统一原版薄片厚度

用户要求：全部物品统一MC原版物品厚度；长度、宽度与玩家比例保持逐件设置。本次美术交付位于 `art/item-thickness/`，没有修改正在接入中的Java或正式资源。

## 明确标准

已读取本地 `build/moddev/artifacts/neoforge-21.1.219-sources.jar` 内的 `net/minecraft/client/renderer/block/model/ItemModelGenerator.java`：MIN_Z=7.5、MAX_Z=8.5，基础厚度1模型单位，即1/16格。居中坐标前后表面为±0.03125格。这个基准来自原版 generated 物品，不是原版方块、盾牌或三叉戟的特殊模型。

用户要求统一，因此本项目盾牌也使用上述薄片基准。纹理16/32/64分辨率不得影响物理厚度。手持长宽可独立变化，局部Z厚度应采用同一视角原版钻石剑的Z缩放；不要跟随武器长度统一缩放。旋转后屏幕投影宽度不等于物品厚度。

## 已交付

- `art/item-thickness/manifest.json`：42项装备及其它58项物品模型逐项记录，含来源、状态、引用、哈希、厚度与接入规则。
- `art/item-thickness/models/`：94份自有PNG对应模型候选，覆盖已有手持/状态及GUI图。普通图采用原版 generated 挤出；三个盾牌front模型已具备真实厚度、独立正反材质及沿透明轮廓生成的侧壁，内部像素间不重复绘制侧壁。
- 其它58项中，普通generated物品沿用现有模型；刷怪蛋沿用原版模板。原有58张物品目录PNG是纹理清单，不宜据其数量推断所有文件都是独立物品；本次按模型目录逐项核对。
- 提供方物品保留原父模型、全部层与状态；清单明确了局部Z规范，不复制或改写第三方美术。
- 源模型、旧版大剑/特大剑、PNG、握点和目标长度未覆盖。本批读取时一张PNG与旧装备清单哈希不同，已按当前实际文件生成并在sourceRevisions记录两版哈希；没有回滚其它人的修改。

模型纹理路径为本批建议路径 `eldencombat:equipment_2d/<原PNG文件名>`；接入方应按manifest/textures中的源文件和目标资源准入，不能只复制JSON而遗漏纹理。此目录是美术候选，尚未进入游戏包。

## 渲染侧必须完成

1. 自有模型应用 `T * R * scale(sx,sy,referenceSz)`，保留当前逐件sx/sy与握点校准。referenceSz从同显示上下文的原版钻石剑display读取，不硬编码成所有上下文都相同。中心锚点Z=0时不改变XY握点。
2. 当前 ItemSpriteGeometry.face 在z=0绘制双面，盾没有厚度也没有侧壁。应使用本批实体薄片盾模型，或在原绘制路径实现相同±1/32局部Z面和透明轮廓侧壁；单纯乘Z缩放不能使零厚度变厚。
3. 当前 EquipmentDisplay、旧版 WeaponDisplayTransforms、提供方display都可能改变Z。分别验证这些路径，避免只修新sprite而旧模型回退仍厚薄不一致。提供方如有自定义非1单位几何，先按实际局部Z包围厚度归一，再按原版上下文缩放，保留完整层和材质。
4. 所有旋转、长度缩放只施加一次。不要在旋转后的世界Z轴压扁物品，也不要修改PNG轮廓来模拟厚度。
5. 验收应覆盖第一/第三人称、左右手、地面、展示框、GUI、盾格挡/背面及弓弩各状态。分别测量局部前后表面距离，并与同视角钻石剑对照；保持长度比例不变。
