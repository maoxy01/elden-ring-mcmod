## 三、审查修正

| 原方案问题 | 修订后的口径 |
| --- | --- |
| 576 quad 估算为 1152 顶点 | 当前逐面提交是 quad×4，即最多 2304 个网格顶点 |
| 开启背面剔除即可零损失减半 | 半透明背面可能参与视觉；仅对近乎不透明的封闭盒体提前跳过背向面 |
| 把 tick 与渲染帧混用 | 几何描述缓存按客户端 tick，提交预算按渲染帧，GPU 时间独立实测 |
| 原版碎块按普通六面盒体核算 | 单列原版方块模型绘制次数，复杂资源包模型成本不能冒充已知 |
| 两个 RenderType 等于全场景两次切换 | 两个自有 RenderType 保持不变，原版方块及其它模组通道不在这个保证内 |
| 纯客户端美术配置走服务端 `/reload` | 配色放在 `assets/`，使用客户端资源重载 |
| 默认全渠道反馈不会失效 | 声音、闪色、震动和渲染均受设置与环境影响，不作绝对保证 |
| 旧武器密度、2048 图集与严格黄金比例 | 以用户已确认的运行资产为准；色彩比例是构图建议，主题战技允许例外 |
| 所有变换后顶点必须吸附网格 | 不用静态建模规则误伤骨骼旋转、运动插值和相机朝向贴片 |
| 构建/预览成功等于兼容通过 | 各实机环境的验证字段保持独立，未测试的一律为 false |

三份原文已备份到 `docs/code-backups/20261012-vfx-pipeline/docs/`。
管线规范顶部的“当前有效契约”是本轮依据，后面的历史稿仅供追溯。

## 四、已接入功能

| 功能 | 实际实现 |
| --- | --- |
| 配色资源 | `assets/eldencombat/fx/palette.json`，按语义 ID 和三级明暗引用；首轮保持原特效配色 |
| 客户端重载 | `FxPalette` / `FxResources`；准备后替换有效快照，坏配置记录错误并保留旧配色 |
| 原生轮廓兜底 | 近处刀光贴片配合淡原生轮廓，远处或贴片不可用时显示原生网格 |
| 手动兼容开关 | 配色 JSON 加 `"slashSprites": false` 可停用贴片，不声称能自动检测光影造成的黑屏或变暗 |
| 距离降级 | 0–16 格完整表现；16–48 格减少碎块；48–128 格简化主形状且关闭贴片/碎块；超过 128 格不画技能几何 |
| 并发压力降级 | 超过 40 个候选特效实体时进入简化档，不删除服务端实体或取消真实技能 |
| 每帧额度 | 自有网格与贴片最多 30000 个提交顶点，先保留主形状并为后续候选预留最低额度 |
| 碎块绘制限额 | 单实体近处最多 12、中距离 6、远处 0；全局每帧最多 32 次原版方块绘制 |
| 描述缓存 | 普通特效按客户端 tick 缓存；黄金波面成型后复用固定相对偏移；资源版本变化失效，使用实体弱引用键 |
| 透明面处理 | 半透明保留双面；近乎不透明的盒体按相机位置跳过背向面；相机在盒内时保留各面 |
| 构建门禁 | `exportSkillFx` 纳入 Gradle `check/build`；导出机器可读预算报告，超标直接失败 |
| 预览门禁 | 浏览器检查读取预算报告，并检查两份生成器源码没有绕过配色 JSON 写死 RGB |
| 剔除防护配置 | Entity Culling 白名单增加 `eldencombat:skill_effect`、`eldencombat:golden_wave` |

黄金波动的中心先行、两侧滞后、定型后相对偏移固定，以及受阻通道规则继续使用原共享前沿算法。
水鸟和命定之死的原生兜底范围扩大，但不据此改变伤害范围。

## 七、未完成和未验证项

以下六个报告字段仍为 false：原版游戏内、Iris、Sodium、Entity Culling、独立服务端、八人性能。

- 白名单配置不等于 Entity Culling 实机验证；需要重启后逐个施放八个战技检查遮挡和视锥行为。
- Iris 需同时检查关闭光影、开启实际光影包，以及关闭贴片的原生兜底模式。
- 尚无 GPU 毫秒数、屏幕 overdraw 或八人 p99 帧时间实测，不作性能达标承诺。
- 按单次施法/玩家精确分组仍缺静态效果的客户端 caster/cast 标识，未实现建议中的 ≤4/≤12 精确上限。
- 极端超过最低轮廓可覆盖数量时，硬预算会限制几何提交；不能保证任意数量的特效都完整可见。
- 没有新增缺乏消费者的 `elements/*.json`、`fx_styles/*.json`；完整形状、声音与阶段绑定仍需和实际战技状态机核对。
- 未新增区域雾、环境建筑、新 Shader 或顿帧实现；这些不属于本轮基础管线接入。
- 跟随型效果在取消、切武器、死亡、离线、跨维度后的完整清理，仍需独立游戏场景验收。

## 八、交接与复验

新增 Java 代码需要重启游戏。之后通过资源包覆盖 `assets/eldencombat/fx/palette.json`，F3+T 可重载。
若直接编辑工作区 `src/main/resources`，先执行 `processResources` 同步运行资源，再按 F3+T，不必重新编译 Java。

在工作区根目录复验：

```powershell
.\gradlew.bat build --offline --no-daemon '-Dorg.gradle.java.home=D:/JDK21'
node tools/skill-fx/check-preview.mjs
```

建议下一步顺序：Entity Culling 可见性、Iris 贴片/原生兜底、Sodium、独立服务端与清理场景、固定八人帧时间基准。
战斗侧若补充 caster/cast 元数据，应保持现有 `ownerEntityId / phase / progress` 语义，不用视觉预算取消真实技能。
