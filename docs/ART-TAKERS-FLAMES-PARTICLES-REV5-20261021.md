# 亵渎战技：粒子火焰版 rev5 交接

2026-10-21。用户否定"用盒子堆火焰"的做法，明确要求：**火焰交给粒子特效、保留地面碎裂、底层铺岩浆效果**；随后追加两条：火焰要越来越高、岩浆面按 MC 方块做成 1×5 格且边缘不规则；最后要求**火焰走到末尾时有冲起的岩浆柱，火焰粒子环绕它**。

本轮只做美术候选，**没有改 Java**。

## 与前几版的关系

| 版本 | 做法 | 结论 |
|---|---|---|
| hybrid (v1) | 5 个火口 + 44 实体盒体原地喷发 | 方向错：真实战技是剑发前推火焰浪，不是原地喷泉 |
| hybrid-rev2 | 加竖向色带、顶端热点外露 | 顶端近白 → "白蜡烛"，退步 |
| hybrid-rev3 | 去掉近白、收尖 | 仍三级台阶 |
| hybrid-rev4 | 改为前推火墙（盒子） | 母题对，但像栅栏/薄板堆叠 |
| **hybrid-rev5** | **粒子承担火焰**，岩浆层 + 地裂帧 + 末端岩浆柱 | 当前候选 |

前三版失败根因一致：**在 MC 里用盒子堆火焰，怎么调色都像积木**。rev5 把火焰整体交给粒子，问题当场消失。

## 结构

- `takers-flames-particles-rev5.bbmodel` — 20 立方体 + 5 locator + 20 组 + 1 动画（1.6s）
- 分层（由下至上）：地面 → `lava_pool` y=0.14 → `lava_hot` y=0.18 → 地裂帧 y=0.24 → 粒子
- **岩浆沟 1 宽 × 5 长**：长边沿**火焰运动方向 Z**，`[-8,0.14,-64]..[8,0.14,16]`
  两条长边的锯齿靠**逐行抖动的 alpha 遮罩**画进 `lava_pool.png` / `lava_hot.png`
  （2026-10-21 修正：最初误做成横向 5×1，用户指出长边应在运动方向上）
- **火焰越来越高**：`flame_rise` 承载组把发射点按关键帧抬高 13 单位（0.81 格），1.05s 到顶后回落
- **末端岩浆柱**：`lava_column` 两根盒子（body + tip），1.15s 冲起至 3.25 格；`column_flame` 发射器（100/s，半径 0.85 格）环绕柱身
- 5 个粒子效果 + 6 条 Effects 关键帧（0.10 裂尘 / 0.15 火带 / 0.16 火星 / 0.65 灰烬 / 1.05 柱火 / 1.12 柱火星）

## 截图方法（重要）

**跳帧截不到粒子。** 必须把时间轴从 0 按 **0.01s 步进**到目标帧，让发射器累积后再截图；直接 `Timeline.setTime(t)` 粒子数为 0。48 张图（oblique / ahead / side × 16）都是这样出的。

## 接入 Java 的注意

1. `particles/*.json` 是 Snowstorm/Bedrock 格式，**只能当参考，不能原样放进 Java 资源包**。要映射到原版岩浆火星、火焰、灰烬/块碎屑。
2. 岩浆层和地裂帧是平面，需按地形分片，不能整张水平面穿过坡地或墙体。
3. 末端岩浆柱是"火焰走到尽头"的高点，运行时按 progress 归一化在末段触发，不要另起寿命。
4. 回血识别（剑身闪光）**未做**。

## 已知缺陷（不掩盖）

- 少数火焰精灵在 Bedrock 预览里渲染成细斜条（精灵图集采样问题），Java 用原版粒子不会复现
- 末端柱身是一根素棱柱，完全靠粒子读成岩浆
- 人类验收未做；`humanAccepted: false`

## 工具坑（本轮实测）

1. `Codecs.project.compile()` 对 `Project.unhandled_root_fields` 做 structuredClone，而它在 Vue 下是响应式 Proxy → 必抛 DataCloneError。**compile 前先 `JSON.parse(JSON.stringify(...))` 换成纯对象**。
2. 重载工程用 `Codecs.project.load(obj, {path})`，`parse` 收的是**对象**不是字符串。
3. **绝不要直接替换 `cube.faces[f]` 为纯对象**——会把 Face 实例换成普通对象，导致 remove/place/undo 全部报 `getTexture is not a function`。本轮就这么把工程搞坏过一次，靠从磁盘重载回滚救回。
4. Blockbench 的 particle 预览需要真实播放/步进；`Timeline.play` 不存在，用 `animation_timeline` 工具的 play。

### 工具坑补充

Animator 的 `keyframes` 是**只读副本**：`an.keyframes.position = []` 或 `splice` 都不会真正删除，反而会越加越多。删键必须用 `manage_keyframes` 工具的 `delete` 动作（按时间点），`create` 动作重建。
