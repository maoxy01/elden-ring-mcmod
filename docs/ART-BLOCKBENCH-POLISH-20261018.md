# Blockbench物品优化

2026-10-18。人类纠正“我让你用blockbench这个工具优化”后，停止脚本候选路线，改在实际连接的Blockbench 5.2.2中编辑。前一份 `item-polish-20261018` 未采用、未验收，生成器已停用。不得将其图像混入本轮成果。

## 实际工具与修改

- 准备程序只把full现行素材转成可编辑薄片并传入Blockbench，不做优化。28件自制物品按登记长度与握点布局，1871个合并矩形薄片，Z跨度全部1单位；各物品XY按自身比例换算，Z不随长度放大。
- 实际优化由Blockbench原生 `Texture.edit / Painter.edit` 完成，45次原生可撤销绘画记录：12件物品45张贴图（含盾牌正背、弓弩拉弦装填、16/32图标）。整理材质色阶与内部孤立色块，保留透明通道、轮廓和握点。没有使用柔边、抗锯齿或高密度碎纹。
- 本轮12件：钩爪、特大武器、拳套、辉石杖、大盾、大矛、圣印记、小盾、软鞭、大弓、弩炮、药瓶。当前优化是材质/碎色层面，不宣称这12件完成了结构重画。
- 16件已采用或手绘物品在工程内只读展示，不改其像素；14件提供方路线不拆贴图、不另造替代品。弩炮姿态校准、full资源、发布白名单、Java和游戏包均未改。

## 证据边界

先核对战斗/统筹的真实最新回合全部结束，命令均终态，未见Java/Gradle进程。本轮未启动战斗或DSH。

截图通过Blockbench原生Preview.screenshot按需WebGL渲染，不以HTML绘制的假3D代替。28件逐件保存同相机、同画布的修改前后对照；遮挡/最小化状态下的app截图可能过期，因此不以这类截图单独证明当前视图。最初全景的相机不适合，已修正后重拍。曾用eval直接触发聚焦遇到事件参数异常；读回确认选择和贴图已切换后，改用原生trigger_action处理，不将异常写成成功。

第一次配对检查发现某张未修改图存在2像素渲染差异：一边是导出前高精度内存坐标，另一边是重新加载后的保存精度。没有放宽差分阈值；改为两边都实际重载已保存工程，再按相同相机重拍，16件未修改物品全部得到精确零差异。

`validation.json`核对原生导出PNG和工程嵌入纹理逐像素一致、45张透明轮廓与源图一致、28份配对渲染（12变化、16不变）、765份full/厚度/用户手绘/运行源码保护不变，以及所有元素厚度1单位。实际执行结果以该JSON为准。保留咒剑原有半透明像素，不把其它物品的二值透明检查扩大宣传。

本轮仍是独立优化候选，尚未替换已采用美术或安装包，也没有游戏内验收。长度和握点的登记不是新完成的游戏姿态校准。

最终已实际执行并通过静态检查。对照页另在1440/768/390逐件检查28份原生视图、45份状态纹理，零脚本错误/加载失败/横向溢出；三张页面截图与12件原生主视图已查看。Blockbench回到保留46条Undo记录的优化工程，绘画模式显示辉石杖纹理，原生模型可继续编辑；临时离屏视图已释放。所有启动的检查命令已结束。
